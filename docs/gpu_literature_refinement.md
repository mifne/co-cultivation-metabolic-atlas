# GPU加速dFBA/LPソルバー開発：文献改訂・マルチ出力・目的関数忠実度・共通解選択規則の統合報告（2026-09-03）

本ドキュメントは、OR16＋NS21 PHBV＋P. freudenreichii の3菌共存dFBAモデルを対象に、GPU加速LPソルバーの精度・速度向上を目的とした複数の取り組みを統合した報告である。文献に基づく機構層の改訂、複数出力補正、目的関数忠実度の回復、およびCPU/GPU共通解選択規則の提案を扱う。すべての数値・結論は原文のまま転記し、未達・未実装のステータスを明示する。最新の結論は末尾の総合結論にまとめる。

## 1. 文献に基づくGPU機構層の改修

（出典：GPU_LITERATURE_REFINEMENT_PLAN_20260903.md, GPU_LITERATURE_REFINEMENT_REPORT_20260903.md）

### 1.1 文献対応表

### 1.2 実装した変更

1. 現行構成（λ=30、K=2,048、最大2,000反復）のGPU軌跡から、独立した3 seeds（20294001、20295010、20296019）×120状態を採取。GPU不採用だった2状態も含めて、同一の上下限・共有培地・菌体量・目的関数でCPU HiGHS厳密解を付け直した。360状態を追加し、辞書を34,344件から34,704件にした。生ラベルとrow seedも保存した。
2. 追加データの学習重みを4とする再学習と、正規化した反応境界違反の二乗損失を加えた再学習を分けて比較した。閉じたPHB/PHV反応等の誤予測に学習時から勾配が働く。
3. 再学習の悪化を受け、予測器を変えない辞書拡張と、前回の正規化・重みを保持する低学習率の継続校正（100 epochs、学習率1e-5）を対照として追加した。
4. 菌種別の独立な混合係数をGPU QPへ導入した。菌種内の物質収支は維持し、共有栄養は引き続き菌種間で連成する。明らかに使えない境界面の候補を除く前処理も追加した。
5. 共有GPUサービスの古い目的関数モード固定を修正し、現在のPHB/PHV切替えモデル、複数出力QP、再試行に対応させた。大きい再試行は小分けし、空きVRAMに応じてバッチ上限を抑える。
6. 辞書の凸結合に限定しない符号付きアフィン投影を診断用に試作した。凸結合なら省略できた制約も検査対象に戻し、全化学量論行列の残差をGPUで確認する。小規模診断では後半状態の収束不足が残り、オンライン既定経路へは組み込んでいない。

### 1.4 結論と残る作業

実装・回帰テストと並列経路の修正は実施した。しかし、全精度基準を満たしたと認定していない。継続校正ではPHA終点誤差が前回の0.513%から0.276%へ低下した一方、3HVモル分率誤差は0.001307から0.030078へ悪化した。菌体量最大誤差も0.026461 g/Lで基準外である。したがって、この校正を総合的な精度改善とは扱わず、採用を見送る。失敗した構成を本番既定へ昇格させず、前回の比較結果と新しい負の結果を両方保持した。最終検証用5 seeds（20286001〜20286005）は未使用。開発基準を通過してから評価する。

次の主要課題は、制約が厳しくなる状態での機構QPの収束と、補正後の出力・正味の栄養移動・菌体増殖を意識した学習である。辞書件数だけ、あるいは単発のニューラルRMSEだけを改善しても、逐次誤差やCPU LPの最適性までは保証できない。CPU LPをGPU推論中に隠れて呼ぶ、誤差基準を緩める、検証状態を教師に混ぜる、PHA終点に補正式を掛ける、といった操作は行っていない。

## 2. GPU複数出力補正

（出典：GPU_MULTIOUTPUT_PLAN_20260903.md, GPU_MULTIOUTPUT_REPORT_20260903.md）

### 2.1 実装

155個の増殖・PHB/PHV・交換フラックスを同時に合わせるGPU QPを追加した。予測値を硬い等式制約にはせず、標準化した予測誤差の重み付き二乗和と参照混合係数からの変化量を最小化する。元の反応境界と共有培地制約を維持する。物質収支は、同じGEMの厳密解を非負・総和1の係数で混合する構造で保持する。GPU上のADMMに加え、未収束の候補からも制約内の改善だけを採用する線分探索を実装した。全境界と共有培地制約を再検査し、目標誤差が改善しない補正は採用しない。これはCPUの3段階LP最適解を保証するアルゴリズムではない。

予測器も再学習した。従来の32,768件に、既に独立収集済みの1,576件を加えた34,344件を使用し、500 epochs、512×512のネットワークで学習した。診断seedの状態を教師データに混ぜていない。サンプル分割の検証誤差と、時系列全体の検証誤差は別物である。

### 2.4 残る課題

1. 別のseedで長時間・低窒素境界・窒素相切替えを重点的に収集する。現状の辞書全体でも到達できない状態があり、検索件数の増加だけでは不十分だった。
2. 各菌種の独立混合をGPU化し、追加データと組み合わせて検証する。検証状態そのものを学習に戻して合格扱いにはしない。
3. CPUと同じ共存→目的関数→交換最小化の順序をGPU上でも近づけ、QP反復回数と速度を改善する。使用率を上げること自体を目標にはしない。
4. 開発用の長時間試験を通過してから、未使用5 seedsで厳格な最大誤差検証を行う。

現状は研究用の非認証構成として保持し、本番用の既定設定は変更していない。オンラインFBAのCPU LPは0回だが、環境更新・Python制御・入出力はホスト側に残る。したがって「プログラム全体がGPU内だけで完結した」とは表現しない。複数出力モードはローカルGPU QP経路で利用可能。未対応の別GPUサービス経路との組み合わせは黙って無視せずエラーにし、従来モードの認証結果の流用も拒否する。

## 3. 目的関数忠実度と精度回復

（出典：GPU_OBJECTIVE_FIDELITY_PLAN_20260903.md, GPU_OBJECTIVE_FIDELITY_REPORT_20260903.md）

### 3.1 背景と問題

現行モデル（OR16＋NS21 PHBV＋P. freudenreichii）において、従来の辞書凸結合＋QP方式ではCPUの3段階LP最適解を再現できず、開発seedでPHA誤差0.513%を達成したものの菌体量誤差0.028451 g/Lで基準外だった。また、独立5シード検証（seed 20286001〜20286005）の最初のseedでPHA誤差3.11865%、菌体量誤差0.0247287 g/Lと不合格となり、2シード目は途中停止した。原因調査の結果、以下の要因が特定された。

1. **比較していたモデルが違う。** 旧GEMでの最大PHA誤差0.861%は、NS21のPHB/PHV修正や第3菌の変更後のモデルに引き継げない。
2. **単一指標の成功と総合合格は違う。** 現行モデルの開発seedでは、従来構成がPHA誤差0.513%を達成していたが、菌体量誤差0.028451 g/Lは基準0.01 g/Lを超えていた。継続校正はPHA誤差を0.276%に下げた一方、3HV分率誤差を0.030078へ悪化させた。「以前は全基準合格」とは扱えない。
3. **制約を満たす予測は、CPUの最適解とは限らない。** 従来の辞書凸結合＋QPは、選ばれたアンカーの範囲内でニューラル予測へ近づく問題を解く。CPU参照の「共通増殖最大化→生産等の目的最大化→交換フラックス最小化」と同一ではない。辞書の件数だけを増やしても、この差は解消しない。
4. **逐次的な誤差増幅がある。** 小さな増殖・正味栄養交換のずれが次時刻の菌体量と栄養残量を変え、窒素制限やPHB/PHV切替えの時点をずらす。ランダム分割のニューラルRMSE改善だけでは24時間後の一致を保証しない。
5. **同じLPの最適解でも交換の内訳が一意とは限らない。** 新たな診断で、同じ目的値を保ったNS21のバリン／ロイシン利用の違いが培地状態を分岐させた。目的値・残差の一致だけで、動的軌跡の一致を保証した点が不十分だった。

### 3.2 原因の切り分け

保存状態（step 0 / 60 / 90 / 119）で、CPU HiGHS dual simplexとIPMを比較し、第3段階の最適値をほぼ保ったフラックス変動解析（FVA）を行った。目的値の許容幅は `1e-8 × max(1, |最適値|)`。この4状態では、両CPU解法の重要フラックス差は最大約3.6e-11、増殖フラックスのFVA幅は最大約2.1e-6、PHB/PHV合成フラックスの幅は最大約9.1e-5だった。内部反応の多義性までは否定していないが、観測された大きな菌体量・組成誤差を「CPU解がもともと大きく不定だから」と説明する根拠は得られなかった。この検査状態は教師データに追加していない。ただし、これは初期の限られた出力・状態の検査結果であり、交換フラックス全体を網羅しておらず、後述の16ステップ目では非一意性が見つかった。非一意性の不存在を示す検査とは扱わない。

### 3.3 実装変更

#### 同一の3段階問題をGPUで解く経路

既存のLP構築処理に差し替え可能な最適化バックエンドを追加した。共通増殖の上限0.005、段階間の99%保持、ライブ目的、交換フラックスの重みはCPUと共通。途中の段階が失敗した場合、前段階の解やCPU解へ黙って置き換えず、そのステップを不採用とする。

- cuOpt 26.8を `.venv-cuopt-26.8` に隔離して導入。従来のPython環境は維持。
- GPU PDLP / Barrierを明示指定。Concurrent、CPU DualSimplex、crossoverは禁止。
- 元の全行列と反応上下限で、GPU上の可行性を再検査。絶対残差上限1e-5。
- 行列の組立て、反応対応、CPU/GPU段階呼出回数、設定、実装ハッシュを記録。
- 途中停止した軌跡に、全期間の終点精度ラベルを付けないよう比較処理を修正。
- CPU参照を再利用するとき、モデルだけでなくCPU実装のハッシュ一致も要求。

#### 数値収束への対処

cuOptの小規模LPは解けたが、実GEMでは内点法の数値エラー、またはPDLPの双対収束遅延が生じた。FP64、前処理の変更、独立行の選択、数学的に冗長な不等式の除去、正の目的関数スケーリングを検証。反応を訓練データの支持集合に限定する案と、微小な二次正則化も診断したが、採用していない。前者は全GEMの最適解保証を失い、後者は目的関数を近似的に変えるため、明確に別の試験として記録した。

HiGHSの**代数的な前処理だけ**を利用すると、初期問題は約6,700変数から約2,400変数へ縮約された。縮約後をGPUで解き、元の変数へ復元する。HiGHSの `run()` は呼ばず、postsolveにbasisを渡さず、CPU simplex/IPM/crossoverの反復上限を0に設定し、実際の反復数も検査する。これはCPU LPへのフォールバックではないが、**全処理GPU常駐でもない**。

cuOpt PDLPでは最初の1ステップの3段階が成功したが、次の交換最小化で時間上限へ達した。そこで、別案としてFP64の有界変数2段階単体法をGPU実装した。ピボット演算・基底の再計算・解の可行性検査はGPU、制御と前処理はCPU。Harris型の比率判定と定期的な基底再計算により、初期の数値不安定性を改善した。現在は基底の再利用とQRによる開始基底の構成も検証している。

**今回の長期検証で採用したLPエンジンはCuPyによるGPU単体法であり、cuOpt PDLP／Barrierの成功結果ではない。** 共通のアダプターを通すが、選択された実装経路は異なる。

| 処理 | 今回の実行場所 |
|---|---|
| GEMの読込み、培養状態の更新、LP組立て | CPU |
| 代数的な縮約、開始基底のQR選択、原変数への復元 | CPUを含む |
| 基底方程式、ピボット更新、価格付け、Phase I修復、残差計算 | GPU（FP64） |
| 反復制御、ピボット添字の取得 | CPUとGPU間の同期あり |
| オンラインのCPU LP最適化 | 禁止 |

「CPU LPなし」と「全処理GPU常駐」は異なる。

基底を反応IDで対応付け、前の基底に不足する方向だけQRで補う変更後、同じ3-step smokeは81.45 sとなり、重要出力の誤差は約1e-12のまま維持された。まだCPUより遅い。初期のGPU共通増殖問題では14,095反復中14,055反復が可行な開始解を作るPhase Iであり、最適化そのもののPhase IIは40反復だった。後半の条件切替えでもPhase Iが支配的になる。従って、次の性能課題は単なるVRAM増量ではなく、開始基底の再利用・修復と逐次ピボットの処理方式にある。

追加のGPU双対単体法は、双対可行な開始条件を満たせない場合が多く、採用を見送った。cuOptへ前処理前の反応上下限を戻す別試験でも、内点法の数値エラーは解消しなかった。これらの負の結果もログに保持している。長期検証中の方式へは混ぜていない。

### 3.4 開発120ステップの経過（失敗と修復）

### 3.6 交換フラックスの非一意性と第4 LP

CPUの全120-step再実行は元のCPU軌跡と一致した。GPUの17-step再現も、保存したGPU軌跡のPHA・菌体量と一致した。したがって実際の分岐を短期再現できた。

最初の大きな培地差は16ステップ目（3.2 h）だった。菌体量・PHAの差は小さいまま、培地のバリンがCPUで0、GPUで0.00205095 mMとなった。GPUではCPUよりロイシンが0.00205095 mM少なく、ギ酸が0.00205095 mM、水素が0.00410188 mM多かった。一方、17ステップ目のGPU入力LPをCPUで解き直すと、GPUの目的値と約1.3e-11以内で一致した。単にGPUがそのLPの最適解を逃したという説明ではない。

16ステップ目のCPU LPの最適面を調べたところ、バリンの正味取込フラックスは約−0.0102549～0 mmol L⁻¹ h⁻¹の幅を持っていた（負は分泌）。目的値許容幅は `1e-8 × max(1, |最適値|)`。この幅にdt 0.2 hを掛けた値が、観測したバリン濃度差0.00205095 mMと対応する。菌体量・PHB/PHVのフラックスがほぼ一意でも、次の時刻に使う培地の状態は一意とは限らない。

この問題は [DFBAlab（Gomez et al., 2014）](https://pmc.ncbi.nlm.nih.gov/articles/PMC4279678/) でも扱われており、動的計算に用いる交換フラックスを優先順位付きで決める方法が示されている。ただし、その優先順位はモデルの定義の一部であり、論文から任意の順位をそのまま流用しない。本件でも「主要出力のFVA幅が狭い」だけを全状態更新の一意性と同一視していた点が不足だった。

菌種別に追跡すると、このバリン蓄積差は「NS21がバリンを新たに分泌した」ためではない。OR16のバリン分泌はCPU/GPUとも約0.0750593 mmol gDW⁻¹ h⁻¹で一致していた。NS21のバリン取込はCPU 0.143208に対しGPU 0.104629と小さく、ロイシン取込は0.0728173から0.111396へ増えた。すなわち、OR16の分泌したバリンをNS21が取り切らない解が選択された。P. freudenreichiiの直接のバリン交換が原因と示したものではない。上記の数値は各菌体量当たりの生フラックスであり、培地全体のmM/hと区別する。

同じ保存解では、OR16のVALDHrなどの内部反応に±1000付近の解もあり、CPU/GPUの内部フラックス差が2000に達しても、対応する正味交換はほぼ変わらなかった。これは内部自由度の大きさを示す。各反応の熱力学的可否やループをこの比較だけで確定しない。全内部フラックスを一意の教師値として近似する設計には注意が必要であり、動的出力を明示した学習・解選択を検討する根拠になる。ただしsurrogate誤差の唯一の原因と切り分け済みという意味ではない。

追加確認として、同じ3段階の生物学的目的と同じ120個の入力を用い、CPUのHiGHS dual simplexをHiGHS IPMへ変更した。全120ステップが完了し、旧CPU参照に対する終点差はPHA 0.000302982%、菌体量6.84567e-6 g/L、3HV分率1.22385e-5だった。この条件ではCPU解法変更だけの差は基準内だった。「非一意だからCPU同士でも必ず1%を超える」という結論ではない。GPUの解選択・数値実装の改善余地は残る。

## 4. CPU/GPU共通の解選択規則の提案

（出典：GPU_SHARED_SOLUTION_RULE_PROPOSAL_20260903.md）

状態：**未採用**。利用者の確認待ち。旧CPU基準は保持し、現在のGPU回帰試験も旧基準で比較する。

### 4.1 なぜ規則を追加するのか

現行の3段階LPでは、最適な増殖・生産・交換L1量を決めても、交換の内訳を一つに決められない場合がある。seed 20286001の16ステップ目で、その幅が次の培地状態に影響した。したがって、GPUの残差許容値を厳しくするだけでは解決しない。

生物学的に同程度に許される複数の解のうち、特定のCPUソルバーがたまたま返した1解だけを真値とみなすことと、同じ数理モデルを実装できていることは区別する。ただし、この違いを理由に旧基準で不合格だった結果を合格へ変更しない。

### 4.2 維持するもの

- 現行OR16・NS21・P. freudenreichiiのGEM、反応、培地、流加、初期値。
- 共通増殖の最大化、99%保持、ライブ目的の最大化、99%保持、交換L1最小化。
- PHA終点相対誤差1%、菌体量最大絶対差0.01 g/L、3HV分率絶対差0.01。
- 全120ステップの完走、元の全制約の検査、GPU経路でのCPU LP禁止。

### 4.3 案A：最適面上での二次ノルムによる選択

3段階目までの可行・最適面を F とし、f = T v を動的状態に必要な出力とする。追加段階を `min 0.5 * ||W T v||_2^2, v in F` と定義する。Wは全対象成分に正の固定重みを持つ。目的値保持の数値許容幅も版管理する。

可行出力集合 T F は凸である。異なる二つの出力がともに最小なら、その中点の目的値は厳密凸性により小さくなるため矛盾する。従って可行集合が空でなく最小値が達成される限り、fは一意となる。内部フラックスv全体は一意でなくてもよい。これは実数算術上の性質であり、実装の収束・残差・1%精度は別途実測する。

Tに含める候補は、各菌の増殖、PHB/PHV蓄積、各菌の交換フラックス。現在の状態更新では菌体量の増殖抑制係数を各菌のフラックスへ掛け、交換・蓄積・CO2積算などを更新するため、集団全体の正味交換だけを固定しても十分とは限らない。状態更新コードから利用する全出力を列挙し、取りこぼしのテストを先に作る。

Wは単位・反応のスケールに依存する。全フラックスを同じ重みで罰することも生物学的中立ではない。測定で支持された重みがない段階では、数理的閉じ方として明示し、複数の事前設定重みで予測感度を別途報告する。旧CPU終点へ合わせて重みを調整しない。水・プロトンだけを除く第4 LP試作とは異なり、対象出力にゼロ重みを設けない。主要目的に小さな二次項を混ぜて優先順位を暗黙に変える方法も避ける。

CPUでは独立したQP実装を参照に使い、GPUでは同じ行列・境界・重み・目的保持を用いる。GPUで近似候補を使用する場合も、QPの収束と元の制約・優先目的を検査する。不合格をCPU解へ差し替えず、未受理として学習データから除く。

注意：ノルムによる一意化は、すべての反応の熱力学的妥当性を保証するものではない。保存解には正味交換をほぼ変えずに大きく異なる内部フラックスがある。閉じた内部循環の有無は別の監査が必要であり、[Schellenberger et al. (2011)](https://pmc.ncbi.nlm.nih.gov/articles/PMC3030201/)のloopless COBRAはそのための追加制約を扱う。一般に混合整数問題へ変わり得るため、単純な連続GPU QPと同じ計算負荷・同じ生物学的モデルとは扱わない。

### 4.4 案B：全動的出力の優先順位付き最適化

DFBAlabの考え方に従い、全動的出力を順番に最適化し、その値を固定する。出力値は一意になるが、優先順位はモデル仮定となる。反応名の文字順は実装上の再現性は与えるが、生物学的根拠にはならない。多数のLPを逐次実行すると高価であり、同じ基底上の多目的処理や基底再利用が必要になる可能性がある。

### 4.5 評価を混同しないための手順

1. 旧CPU、旧GPU、GPU第4 LPの結果を保存する。不合格履歴を削除しない。
2. 共通ルール採用後、別名・別ハッシュでCPU/GPU双方を実装する。
3. 既に見た条件で、旧CPUに対するモデル変更の影響と、新CPUに対するGPU実装誤差を二つの別表で示す。新CPUとの一致を旧CPUとの一致として書かない。
4. 合成QPと同一状態の実GEMで、目的保持・可行性・出力一意性・CPU/GPU一致を確認する。
5. 24 h回帰を通過後、未使用seed 20286101–20286105を事前固定し全5条件を報告する。
6. 正確さを確認してから環境数スケーリング・計算時間を測定する。重み感度はソルバー精度とは別のモデル不確実性として報告する。

- **文献改訂（セクション1）**：DAgger収集、境界損失学習、独立混合等を実装したが、全精度基準を満たす構成は得られなかった。継続校正でPHA誤差は改善したが3HV分率が悪化し、採用見送り。
- **マルチ出力補正（セクション2）**：λ=30でPHA誤差0.513%を達成したが、菌体量誤差0.028451 g/Lで基準外。辞書の表現範囲不足が確認され、独立混合のGPU化が未実装。
- **目的関数忠実度（セクション3）**：GPU単体法＋修復により開発120-stepで極小誤差（PHA 5e-8%）を達成。しかし独立5シードの最初のseedで不合格（PHA 3.12%）。原因は交換フラックスの非一意性と判明。第4 LP追加により同じseedの回帰合格（PHA 0.0021%）を得たが、未使用5シードの検証は未完了。速度面ではCPU超えに至らず、Phase I支配が課題。
- **共通解選択規則（セクション4）**：二次ノルムまたは優先順位付き最適化の設計案を提示。未採用。

**最新の結論**：device-pivot＋LU再利用版は120-step回帰に合格したが、独立5シード検証は途中停止・不合格を含む。第4 LP追加版は同じseedで回帰合格したが、未使用5シードの検証は進行中。現時点で本番既定を変更していない。次の優先順位は、(1) 未使用5シードの凍結検証完了、(2) 交換フラックス非一意性への根本対策（共通解選択規則の採用判断）、(3) Phase I高速化による速度改善、である。
