# 完全GPU化・PHA精度1%に向けた実装結果（2026-09-03）

追補：この文書は総PHA補正までの結果を記録している。複数出力QPと再学習による
最新の診断結果は `GPU_MULTIOUTPUT_REPORT_20260903.md` を参照。
開発用1 seedではPHA誤差0.5125%・オンラインCPU LP 0回を確認したが、
菌体量誤差0.028451 g/Lは基準外で、総合認証は未達のままである。

## 結論

**オンラインFBAを120ステップすべてGPUで処理することは確認できたが、
PHA終点誤差1%との同時達成は未達である。認定済みモデルには昇格しない。**

対象は OR16 + 修正済みNS21（PHB／PHVを区別）+
P. freudenreichii subsp. shermanii。以前の旧3菌モデルで得た最大誤差0.861%は、
このモデルの精度証明には使用していない。

ここで「完全GPU」は**オンラインのFBA数値解法にCPU LPを使用しない**という意味。
Pythonによる環境の状態更新、データ入出力、オフライン教師解作成はCPUに残る。
実験培養や生物学的予測精度を検証したものではない。

## 最終コードでの実測

同一初期条件・同一アクション列でCPU参照と比較。初期NH4は0.05 mM、
刻み幅0.2時間。下表は**異なる構成・異なるseedの単一試験**であり、
5 seedの独立認定試験や学習時間全体のベンチマークではない。

| 項目 | 短期試験 A | 長期試験 B |
|---|---:|---:|
| ステップ数／模擬時間 | 24／4.8時間 | 120／24時間 |
| seed | 20260901 | 20260913 |
| 辞書件数 | 34,088 | 34,344 |
| QP候補数／再順位付け範囲 | 512／2,048 | 2,048／4,096 |
| neural順位重み | 0.25 | 0.0 |
| PHA終点相対誤差 | **0.6904%** | **13.0530%** |
| GPU採択回数 | 24/24 | 120/120 |
| オンラインCPU LPステージ実行回数 | **0** | **0** |
| 最大菌体量絶対誤差 | 0.03530 g/L | 0.11613 g/L |
| 3HVモル分率絶対誤差 | 0.01465 | 0.01990 |
| GPU実行時間 | 6.8840秒 | 98.0266秒 |
| 認定 | 不合格 | 不合格 |

AはCPUとGPUを順番に新規実行した。CPUは23.4133秒で、生の所要時間比は3.40倍。
ただし菌体量・組成の基準を満たさないため、**精度を維持した学習高速化とは呼べない**。
Bは既存の同一seedのCPU終点を再利用した診断試験であり、CPUとの速度比は算出しない。

採用基準は最大PHA誤差1%、菌体量誤差0.01 g/L、3HVモル分率誤差0.01、
全ステップGPU採択・CPU LP 0回。PHAがゼロ同士、途中終了、GPU解失敗による
更新省略を成功に数えない。独立の最終5 seed（20286001～20286005）は未使用のまま保留した。

## 実装した変更

1. **教師データの整合性修正**：追加学習・DAgger処理に菌種構成と初期NH4を渡し、
   CPU再ラベル時にPHB／PHVを含む動的目的関数を復元するようにした。
   入力20,599次元が再ラベル前後で一致することを検査する。
2. **辞書拡充**：32,768件に、独立な長軌跡960件、GPU到達状態の正解360件、
   初期低窒素状態の境界サンプル256件を追加し、34,344件とした。
   元の生産用辞書は上書きしていない。GPU失敗状態22件も正しい状態で再ラベルした。
3. **予測器再学習**：長軌跡960件を加えて500 epoch学習。
   サンプル単位の保留データに対するPHAフラックスRMSEは0.630から0.347に低下。
   これは長期ロールアウトの独立精度検証とは区別する。
4. **GPU QP投影の拡張**：単独で実行可能な候補だけでなく、単独では実行不能な候補を
   混合して目標に近づけるADMM補正を追加。PHA予測値±0.25%の補助制約を置くが、
   これはCPU値への1%保証ではない。目標が実現できない場合は物理的に実行可能な
   GPU解を保持し、補正失敗を記録する。CPUへ無断で切り替えない。
5. **計算の削減**：全候補が厳密に満たす制約を反復演算から除外し、最後は全制約で検査。
   小さい制約空間でのGPU倍精度Cholesky／Woodbury更新を使用する。
   再順位付けでは全6,733反応ではなく155決定フラックスのみを事前キャッシュする。
6. **検証の修正**：QPの残差は混合後の実際の返却解で計算。
   CPU LPは実行箇所で直接計数し、GPU-only指定で有効GPUソルバーがなければ停止する。
   実行コードのSHA-256も新しい測定結果に保存する。

関連テストは**33件すべて通過**。CUDAの実機はRTX 4060 Laptop GPU（8188 MiB、
driver 591.74）。長期試験BのPyTorch最大割当VRAMは1,417.65 MiBだった。

## なぜ1%が残るのか

最初の診断状態では、辞書全体の単独実行可能候補155件の最大PHA質量フラックスは
7.705だったのに対し、CPU参照は8.021だった。予測器は7.983を予測できていたが、
従来の投影が単独候補に戻していたため約3.9%の誤差が残っていた。

オフラインで同じ候補の凸包をLPで調べると8.468まで到達できたため、
GPU上の候補混合を改良した。この改良で短期のPHA誤差は0.69%まで下がった。
しかし、**線形制約を満たすこと、PHAだけが近いこと、CPUの辞書式最適解に近いことは別問題**である。

現段階の投影には、CPUの「共存増殖率→動的目的→交換フラックス最小化」という
三段階最適化との最適性ギャップ保証がない。長期試験では菌体量・交換フラックスもずれる。
NH4等の状態誤差による生産期切替のずれは、次にステップ単位で検証すべき仮説である。
全期間の1%達成に必要なのは、単純な辞書件数・VRAM使用量の増加だけではない。

## 次の実装計画

1. CPU／GPUの同一状態比較を各ステップで行い、増殖、PHB、PHV、NH4、酸素、
   炭素源・主要分泌物の誤差を分解する。時系列のずれと単一状態の解誤差を区別する。
2. 総PHA一変数への補正から、PHB／PHV・菌体量・主要交換フラックスを同時に扱う
   投影へ移行する。CPUの三段階目的を維持する制約または最適性検査を追加する。
3. 有限辞書内で足りない状態は、GPU上の全反応空間LP補正／能動集合補正を検討する。
   追加データは誤差の大きい状態へ限定する。精度基準は緩めない。
4. 120ステップの診断基準を満たしてから、未使用5 seedで認定・公平な速度測定を行う。
