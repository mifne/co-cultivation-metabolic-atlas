# 学習中の反復計算を半減する試験 — 2026-09-07

## 結論

**半減は未達である。** 初回準備の短縮をこの達成に数えない。新しい方式は実験用の
明示オプション／probeに限定し、PPOの既定経路も元LPの精度基準も変更していない。

対象は32個の異なる環境の保存maxmin LP、step 2～8。step 2を初回、step 3～8を反復区間とする。
実際のPPO学習全体、因果的dFBA全段、120ステップの時間ではない。
前回の同一ソース・3反復比較による基準は、GPU反復区間3.470秒、CPU16 workers 2.229秒。
今回の目標は**同じ更新・求解・元LP検証込みで1.735秒以下**である。

今回の終了時の対照実行はGPU 3.566秒（単回）。目的上限を固定する補助問題のGPU方式は
3.679秒（単回）だった。両者とも各224件が元LP認証と独立直接双対検証を通過したが、
速度優位や半減を示さない。試作と対照で解法が異なり、一部ソースも異なる探索的試験なので、
これらに統計的有意差・信頼区間は付けない。

## 律速の直接計測

32環境のstep 3を同期付きで診断した結果、求解0.529秒に対し、cuDSS数値分解11回の
完了待ちwall時間が0.204秒、三角求解22回が0.048秒だった。残りにはGPU配列演算、
方向の認証、ラインサーチ、Python制御、同期が含まれる。
行列分解だけで約39%を占めるため、補正や検査の小変更だけでは半減が難しい。

native呼出しがhostへ戻る時間と、GPU処理が完了する時間を分離して計測した。
CUDA event区間はlaunch gapも含み、GPU busy率ではない。診断自体に同期を入れているため、
このprofileを非介入の性能比較やGPU使用率の証拠として使わない。

## 実装した候補と判断

| 候補 | 観測 | 判断 |
|---|---|---|
| 双対Schur補行列 | 分解次元5,808→2,015。非ゼロ数44,248→53,029。32環境で認証通過、速度改善なし | opt-in、既定不採用 |
| 多重中心性補正 | 4環境の反復で分解11→8回、8→6回。追加求解込み0.496/0.346秒 | 反復数だけでは半減にならない |
| primal/dual独立更新幅 | 共通幅とのmerit比較で保護。認証通過するが半減なし | opt-in |
| 環境間の分解共有＋複数右辺 | 4環境を2環境ずつ共有。次時刻で補正が増え、元LP認証に失敗 | 既定不採用、失敗時間は速度比に含めない |
| 固定分解DR＋Anderson | 500反復でも違反が残る | 未認証、不採用 |
| 目的上限固定の実行可能性IPM | 32環境で初回分解42→18回、全224件認証。しかし反復区間3.679秒 | 初回改善と反復改善を区別 |
| 違反二乗の減衰Newton | 30反復で元LP未認証 | 未認証、不採用 |
| 前回フラックスのray縮小／成分別再スケール | 元LP検証で不合格。GPU IPMへ戻して全7時刻を進めても、各時刻で再分解が必要 | 辞書なし再利用案も、このデータでは不十分 |

目的上限固定は、単一目的係数と有限の箱最適値が存在する場合だけの**補助問題**である。
その箱最適値で実行可能解が見つかれば元LP最適性を検証できるが、見つからないことは
元LPの不可解・共存不可能性を意味しない。元モデルの境界を緩めたわけではない。

ray試験では全制約と現在の境界から許容スカラー区間を計算した。丸め誤差用の提案帯は
1e-7（最終primal基準1e-5より厳しい）で、最後の元LP判定は変更しない。
成分再スケール後も、step 3の上限を制限したのは元LPの0-based行4738だった。
4環境でこの行のray係数が約0.988～0.993、許容値が約0.000244～0.000684となり、
共通縮小係数の上限は0.000247～0.000689、他制約から必要な下限は0.189～0.573だった。
単純な縮小では両立しない。どの代謝物かは反応・交換slotへの対応付けが必要であり、
この行番号だけから生物学的原因を断定しない。

## 精度と適用範囲

- 元LP primal違反 ≤1e-5、dual違反 ≤1e-7、相対KKT gap ≤1e-7、独立直接双対gap ≤1e-7を維持。
- IPM系の候補では元Newton forcingと実際のmerit減少の検査を維持。
- その他の補助提案器は元LP最適解を名乗らず、独立の元LP認証に通った場合だけ採用可能。
- GPU経路でCPU LP optimizer呼出しは0。現在・未来のCPU参照解はGPUへ与えていない。
- 初回構造解析・入力準備・独立監査にはCPUを使う。「完全GPU内完結」とは呼ばない。
- 未認証候補、fallback費用、初回準備を除いた部分時間で有利な速度を作らない。

## 次に必要な改訂

今回の結果から、共有factorをさらに広げたり、反復数の上限を機械的に半分にしたりする
方針は取らない。まず現在の律速制約行を反応・交換slotへ対応付け、前時刻から変わる
有効制約と、その修正に必要な反応方向を絞る必要がある。

1. 行4738等の強い制約変更を入力生成コードへ逆追跡し、全6遷移の支配制約を計測する。
2. 単なるflux振幅では足りないため、等式を保つ反応の組合せ変更を低次元のGPU補正空間へ追加。
   過去GPU解と現在入力だけで構成し、現在CPU解を教師として使わない。
3. 4環境の元LP認証・更新込み時間が両方改善する場合のみ32環境へ拡張。
4. 最終採用には同一ソース・3反復以上・順序ローテーションでGPU/CPU16を再比較する。
   半減とCPU超えが未確認の間はPPOへ既定適用しない。
