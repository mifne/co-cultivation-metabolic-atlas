## 3. 最初の測定結果 — デバイスピボット + 共有LU (出典: `GPU_SPEED_RECOVERY_PLAN_20260903.md`)

### 3.1 保存状態テスト

デバイスピボット/リファクタプロトタイプは、全9つの保存状態ケース（ステップ16, 17, 115、各交換段階内の3つの主要段階 + 第4LP）に合格。各バックエンドで12回の実際のGPU LP呼び出し、CPU LP呼び出しなし。

| メトリック | 参照GPU | デバイスピボット + 共有LU GPU |
|---|---:|---:|
| 9ケースの合計時間 | 191.103秒 | 123.911秒 |
| 最大再計算元LP違反 | 2.174e-10 | 4.463e-9 |
| 記録された目的/残差チェック | 合格 | 合格 |

- **時間比率**: 1.542（35.16%短縮）。これは保存状態ワークロードに対する結果であり、CPU高速化、フルdFBA高速化、または独立した精度クオリフィケーションではありません。
- **実行回数**: ケースあたり1回、固定バックエンド順、ウォームドCUDAライブラリ、信頼区間なし。
- **遅くなったケース**: 9ケース中2ケースが遅くなった。
- **GPU実装間の最大サンプリング後タイネット交換速度差**: 4.261e-7 mM/h（フル軌道保証ではない）。
- **生データ**: `results/pf_gpu_device_saved_comparison_20260903.json`
- **独立再評価**: `results/pf_gpu_device_saved_comparison_audit_20260903.json`

### 3.2 分離キャッシュ実験（非選択）

`exchange_primary` と `exchange_tie` の基底キャッシュを分離する実験。元のバックエンドは両方に `parsimony` を使用するため、タイLPが先行するプライマリキャッシュを上書きする。分離は性能を向上させるとは限らない（大きな栄養/状態変化後は以前の基底が悪化することもある）。

- **結果**: 数値チェック合格だが、時間は171.191秒（分離なし123.911秒に対して）。ステップ115の交換段階は68.752秒（分離なし20.649秒に対して）。
- **ステータス**: **選択されていません**。明示的なオプションとしてのみ利用可能。
- **監査**: `results/pf_gpu_device_variants_audit_20260903.json`（27記録ケース、3バリアント、各バリアント12実LP呼び出し、同一状態チェックのみ）

83件の複合回帰/ユニットテスト合格（6.60秒）。ログ: `results/pf_gpu_device_combined_tests_20260903.log`。これには30件の新しいデバイス/監査/キャッシュ/ランチャーテストが含まれます。重複する中間合計を加算しないでください。

## 4. スコープと残作業 (出典: `GPU_DEVICE_QUALIFICATION_20260903.md`, `GPU_SPEED_RECOVERY_PLAN_20260903.md`)

- **本検証のスコープ**: 特定のCPU参照との数値的一致を有限テストセットで確認するものであり、実験生物学、広範なパラメータ一般化、PPOトレーニングを対象としません。
- **未達事項**:
  - ホストのプリソルブ/QR/ポストソルブは残存。
  - フルデバイス常駐は未達成。
  - 競争力のあるCPUソルバーに対する高速化は未達成。
  - マルチ環境バッチ処理と検証済み基底再利用には、独自の精度/スループットベンチマークが必要。
- **制限**: より高速な保存状態LPは、より高速な24時間dFBA、PPO学習、または完全GPU常駐環境を意味しません。CUDA Graphsは起動オーバーヘッドを削減しますが、必要なLPピボット数を減らしません。LU分解の再利用は反復線形代数を削減しますが、LP問題自体を削減しません。
- **参照文献**: [CUDA Graphs](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html), [CuPy LU factorization](https://docs.cupy.dev/en/stable/reference/generated/cupyx.scipy.linalg.lu_factor.html), [basis reuse in dFBA](https://arxiv.org/abs/2003.03638)
- **長期ジョブランチャー**: `scripts/launch_recorded_job.py` — 別のスーパーバイザ/ワーカーPID、`/proc` 開始時間、コマンド、スレッド設定、終了コードを記録。定期的な自動化ではなく、WSLシャットダウンや電源喪失に耐えられず、欠落した終了レコードは生存確認が必要。
