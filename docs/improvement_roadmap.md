# dFBA-RL システム改善ロードマップ (v1.2)

## 0. プロジェクト概要
天然ゴム分解微生物コンソーシアム（3種）を対象とした、dFBA（動的フラックスバランス分析）と強化学習（PPO）による動的制御システム。

---

## 1. 現状の問題分析（2024-04-25 更新）

### 🔴 **Critical: FBAが完全に失敗している**

#### 現象
- 全ての種で増殖速度 μ=0.0000 1/h（バイオマスが全く増えない）
- ゴム分解量が 0.000000 g/L（分解が起きていない）
- エピソードが200ステップで打ち切られる（早期終了条件に到達しない）

#### 根本原因（診断結果）
1. **取り込み制約が厳しすぎる**
   - `set_uptake_constraints()` で必須基質（glucose, O2）の取り込みが過度に制限
   - Monod式の Km=0.1 が高すぎて、20 mM のグルコースでも飽和しない
   - 濃度 < 0.01 mM で取り込みを完全停止 → 微量栄養素が枯渇すると即死

2. **初期培地条件の問題**
   - `_initialize_medium()` で交換反応の境界値が保守的すぎる
   - 一部のモデルで必須栄養素の交換反応が閉じている

3. **報酬関数の設計ミス**
   - FBA失敗（μ=0）でも diversity_reward が 27.62 点と高い
   - 何も起きていないのに平均報酬 5523.73（学習シグナルが歪んでいる）

## Phase 1A: FBA動作の緊急修正（最優先）

### 目標
FBAを成功させ、バイオマスが増殖する状態を実現する。

### 1.1 診断機能の強化 ✅ 実装予定

**ファイル**: `src/dfba_simulator.py`

**修正内容**:
- FBA失敗時に以下を出力：
  - 各交換反応の境界値 `[lower_bound, upper_bound]`
  - 対応する代謝物濃度
  - 目的関数（バイオマス反応）の境界値
- 制約緩和テストの結果を詳細表示

**期待効果**: どの制約が原因でFBAが失敗しているか特定できる

---

### 1.2 取り込み制約の緩和 ✅ 実装予定

**ファイル**: `src/dfba_simulator.py` - `set_uptake_constraints()`

**修正内容**:
```python
# 修正前
Km = 0.1  # 必須基質
max_uptake_rate = 20.0

# 修正後
Km = 0.01  # 0.1 → 0.01（より低濃度で飽和）
max_uptake_rate = 50.0  # 20 → 50（取り込み速度を2.5倍に）

# 完全停止条件を削除
if concentration < 0.01:
    # 削除: 微量でも取り込み可能にする
```

**期待効果**: 
- グルコース 20 mM で十分な取り込み速度を確保
- 微量栄養素の枯渇による即死を防ぐ

---

### 1.3 初期培地条件の見直し ✅ 実装予定

**ファイル**: `src/dfba_simulator.py` - `_initialize_medium()`

**修正内容**:
- 全ての取り込み反応（lower_bound < 0）を完全に開放
- 元の下限値をコメントで保存

**期待効果**: モデル構造の問題と培地条件の問題を切り分け

---

### 1.4 報酬関数の修正 ✅ 実装予定

**ファイル**: `src/rl_environment.py` - `_calculate_reward()`

**修正内容**:
```python
# FBA失敗時のペナルティを追加
if all(s.growth_rate == 0.0 for s in state.species.values()):
    return -50.0  # 全種が増殖していない場合

# diversity_reward の計算条件を厳格化
if total_biomass < 0.01 or avg_growth < 0.001:
    diversity_reward = -10.0  # バイオマス不足または増殖停止
```

**期待効果**: 
- FBA失敗時に明確な負の報酬
- 学習シグナルの歪みを解消
