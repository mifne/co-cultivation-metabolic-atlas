# 3種共培養代謝マップの要件定義

作成日 2026年9月22日。初版の実装前に作成。

## 目的と範囲

OR16、NS21、P. freudenreichii の実装済み代謝モデルと、dFBAが扱う共有培地・ゴム分解・PHA蓄積の関係を、KEGG mapのように経路を辿れる図として可視化する。KEGGの画像を複製せず、プロジェクト固有の配置・日本語説明を作る。

初版はローカルで開く科学用ビューアとする。全体図から、実際の反応式・上下限・遺伝子規則・代謝物IDへ移動できる。実験による3種共生の証明や、実フラックスの表示と混同しない。

## データと根拠

- `main.load_requested_models(None, 'pf-helper3')`で読み込む3種を対象とする。生理モデルのB12注釈整理を適用する場合は、その変更内容も保存する。
- SBMLの反応、代謝物、化学式、区画、GPR、交換境界を抽出する。SBMLと関連ソースのSHA-256、抽出日時を記録する。
- 共有プール名は現行のcanonical_metabolite_idと交換反応マッピングに従う。名前の類似だけで代謝物を同一視しない。
- ゴム→C30オリゴマー→ODTDなど、dFBA側の動的反応はSBML反応と区別する。
- 背景培地63成分等の特定条件は、参照設計ファイルとともに表示し、普遍的な培地として扱わない。
- 静的な反応存在、取り込み可能な境界、動的モデルの仮定、実測事実を区別する。交換可能性は分泌・取り込みの実行や完全な代謝経路の成立を意味しない。
- RoxA/RoxBの異種発現は研究室で未成功。酸素応答は今後クルードで検証する計画であり、実測済みの固有定数として表示しない。B12依存の種間供給も確立済みの矢印にしない。

## 表示と操作

1. 全体図：菌種ごとの色、共有培地、ゴム分解、PHA貯蔵と生理機能を配置する。初期状態で読める経路数に絞る。
2. 菌種・対象プール選択：交換反応の方向を上下限から表示する。閉鎖境界は閉鎖と明記する。
3. 反応検索：ID・名称・代謝物・GPRで検索し、反応式、モデル上の上下限、注釈を参照できる。選択反応の基質／生成物を図示する。
4. 凡例・情報欄：図の線の意味、未校正事項、抽出元を常時参照できる。
5. 全体図をSVGとして保存できる。背景データはJSONとして別途保存し、閲覧用HTMLには埋め込む。

## 技術スタック

|層|採用技術|理由|
|---|---|---|
|抽出|Python 3、既存COBRApy、現行ローダー|実行系とID・モデル選択を合わせる|
|成果物|JSON、単一HTML、SVG|サーバー・外部CDN・ネット接続なしで再閲覧できる|
|表示|標準HTML/CSS/JavaScript、SVG|ビルド依存を抑え、経路配置と詳細図を制御する|
|配置|全体図は手動配置、選択反応は基質・反応・生成物の3列|全反応を同時に描くことで生じる重なりを避ける|
|検証|抽出整合性チェック、ブラウザ操作、画面確認|科学的意味と操作の両方を確認する|

公開Webサイトとしてのホスティング、React等のフレームワーク、DB、外部APIは初版には不要。KEGG IDは元モデルに注釈が存在する場合にのみ提示し、KEGG配置や対応を推定して付与しない。

## 受入基準

- 3種それぞれの反応数・代謝物数が読み込みモデルと一致する。
- 反応詳細に存在しないIDや架空の実測フラックスを表示しない。
- 共有プールの交換方向が現行モデルの上下限と一致する。
- 菌種切替、検索、反応選択、SVG保存が動作する。
- 表示中のデータが静的モデルであることを明記する。線の太さを実測フラックスと説明しない。
- 図とJSONの出典・再生成方法を残す。既存シミュレーションと計算結果を変更しない。

## 将来の拡張

菌種別・反応別の時系列フラックスが保存され、使用モデルと単位が検証できた段階で、時刻・条件選択とフラックス表示を追加する。初版では既存終点結果から反応フラックスを逆算しない。経路ごとの自動レイアウトやKEGG対応の拡張は、注釈被覆率を確認してから行う。

## Cytoscape.jsへの構成変更

2026年9月22日、ユーザーの指定により表示エンジンをCytoscape.jsへ変更する。本節を上記の表示方式に優先する。デスクトップ版の改変は行わず、専用HTMLビューアにライブラリを組み込む。

- Cytoscape.jsをnpm公式レジストリから取得し、バージョン・SHA-256・MITライセンスをローカルに保存する。実行時のCDN依存は設けない。
- 全体図はpreset配置、反応詳細は基質／反応／生成物を明示する二部グラフとする。パン、ズーム、ノード移動、全体に合わせる操作を追加する。
- 共有プールを起点とする交換反応グラフも用意する。菌種固有ノードIDを維持し、共有プールへの接続を明示する。
- SVG保存に加え、表示中のネットワークをCytoscape.js JSONに保存できる。反応ノードにGPR・上下限・元IDを保持する。
- 全反応JSONのエクスポートも作る。全ネットワークを初期表示せず、必要な局所だけを展開する。
- 公式仕様の参照先：https://js.cytoscape.org/ および https://manual.cytoscape.org/en/latest/Supported_Network_File_Formats.html

## 階層表示の改訂（2026-09-22）
3細胞をCytoscape compound nodeとして分離。全6,733反応を各菌種の分類に一意に割り当て、細胞→分類→40件単位の全反応一覧→化学量論詳細へ展開する。分類はsubsystem優先、未注釈時は名称ベースの索引であり、確定した経路分類とは区別する。ズーム閾値は各階層の初期fit倍率に対して相対設定する。手動展開・折りたたみと自動切替の無効化も提供する。共有培地は全交換プールから選択可能。

## Escher統合
経路詳細にはEscher 1.8.2本体（MIT）をローカル同梱して使用する。円形代謝物、反応線・反応名、補酵素の小ノード、可逆矢印、ズーム操作を採用。Cytoscape.jsは3細胞を区別した階層表示を担当する。実GEMの化学量論からEscher JSONを生成し、全分類を6反応単位で閲覧可能にする。これは自動配置図であり、手動校正済みKEGG/Escherマップではない。共有の主要代謝物ノードは同一IDで接続し、補酵素は読みやすさのため各反応側に重複描画する。モデルデータを外部サービスへ送信しない。
参考: https://escher.github.io/ 、 https://escher.readthedocs.io/en/latest/development.html

## 交換境界と全反応表示（最新要件）
細胞全体表示では交換を物質群ごとに細胞の左縁へ配置し、内側の輸送帯を経由するモデル接続を示す。細胞拡大では6反応のページ制限を廃止し、モデル全反応・全代謝物・全化学量論辺を表示する。区画間反応を輸送として区別。名称ベース分類の「輸送」とは判定基準が異なる。ラベルはズームに応じて表示、ID検索・選択・分類による強調を提供する。Escherは任意の分類全反応を制限なく開く補助表示として維持。自動階層切替はユーザーのズーム操作時のみ行い、リサイズやfitで切り替えない。
ブラウザー検証：NS21の2798反応、1786代謝物の表示、PHB_syn検索と反応式・GPR表示を確認。

## 培地起点・連続探索要件
培地成分→交換→輸送→細胞内代謝を横方向の流れとして提示。選択経路を濃く、隣接分岐を淡く表示し、画面移動で先を描画する。定量フラックスがない間は線幅を流量と見なさず、方向付き接続探索と明示する。培地参照値と仮想起点を区別。経路検索、Escher周辺図への往復、画面領域ベースの段階描画を提供する。
