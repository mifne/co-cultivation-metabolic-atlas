追補：この文書の共有酸素参照に続き、背景C/N会計・窒素配分・維持代謝・死滅・PHA再利用とB12注釈の新経路を実装した。[生理モデル実装の説明](PHYSIOLOGY_IMPLEMENTATION_20260908.md)を参照。本書の旧23ケースの数値結果は当時の参照版に対する記録として保持する。

[修正前に固定した問題一覧](CULTIVATION_MODEL_AUDIT_20260908.md)の41項目（A:13、B:13、C:15）に対する対応記録。実装の整合性を直した範囲と、生理学的な仮定・実測を必要とする範囲を区別する。**今回の修正は実培養によるモデル検証の完了、3種の安定共生、または3種の生産優位の証明を意味しない。**

最終ソースでのテストと23ケースの再計算結果を末尾に記録した。途中の旧版に対する検証件数と区別する。

## 参照計算の版と適用範囲

新しい参照経路は [AuditedDFBASimulator](../src/audited_dfba.py) の `audited_cultivation_v2`。`separate` FBAとSciPy/HiGHSによる明示的なLP制約を使用する。[cultivation_numerics.py](../src/cultivation_numerics.py) が共有在庫と酸素移動の計算を担う。

従来の `src/dfba_simulator.py` と `src/resolved_dfba.py`、既存の教師・比較結果は保存した。新参照は必要な処理を上書きする別経路であり、旧結果を修正版の結果へ置き換えてはいない。環境・モデル選択・来歴検査などの周辺コードには変更があるため、旧データへの再追記は、昔と同じファイル名という理由だけでは許可されない。

新参照で扱う量は、培地濃度がmmol/L、菌体量がg/L、時間がh。PHAは3HBと3HVを別々にmmol/Lで保持し、それぞれ0.08609、0.10012g/mmolで質量へ換算する。貯蔵上限では菌体量を**PHAを除いた菌体質量**として扱う。実測DCWやOD600との対応は未校正である。

分類の意味は次のとおり。

- **実装修正**：再現できる会計・制御・評価の不整合を、指定した経路で変更した。
- **仮定を明示**：計算規則や未校正の値を出力・設定に記録した。生理学的な正しさを確認した意味ではない。
- **未解決**：実測・GEM再構築・新しい数理モデルなどが必要。実装修正済みの関連箇所があっても、根拠の不足は残る。

一項目に数値的な不整合と生物学的な仮定が含まれる場合、分類を併記する。

## 追加で確認・対処した事項

### LPの最適判定だけでは不十分な数値解

最初の21条件の再計算で、2種の基準条件と細刻み条件が元スケールのLP残差検査に失敗した。全計算を停止し、失敗LPと部分出力を `results/audited_symbiosis_attempt1_20260908/` に分離した。捕捉したLPはソルバーの最適判定にもかかわらず等式残差2.48e-7で、受理上限1e-7を超えた。同じLPをdual simplex・presolve無効・ソルバー許容誤差1e-10で解くと1.36e-12になった。

新参照では主目的LPを検査してから二次の交換選択LPを作る。双方で元スケールの等式・不等式・境界残差、双対実行可能性、主双対ギャップを検査し、不適合時だけ同じLPを最大3解法で試す。培地・時刻・制約は再試行で変更せず、受理許容誤差も緩めない。全失敗なら培養状態を無効化する。

`solve_attempts` は再試行を含む生のソルバー呼出数、`solve_successes` はそのうち検査を通った回数。`lp_requests` / `lp_certified_requests` は論理的なLP要求/最終受理数である。拒否した解は `rejected_lp_trials` に種・時刻・目的・残差・LPのSHAとともに残し、再計算で回復した失敗も隠さない。停止していた2種条件の2時間予備計算は、1,565要求をすべて認証、4回の不適合解を再試行で回復し、受理解の最大収支残差1.61e-9を確認した。

次の本計算では、乳酸無供給条件で実質ゼロの増殖に2.53e-10 h⁻¹の必須下限を課すと、後段の貯蔵LPが不成立になる問題を確認した。この試行は `audited_symbiosis_attempt2_20260908` に保存した。新参照は増殖配分の絶対精度を `growth_allocation_tolerance_h_inv=1e-9` と明示し、適用下限を `max(基本下限, 0, 指定下限−1e-9)` とする。指定値・適用値・解の値・不足量を記録し、解の不足量が1.1e-9 h⁻¹以内であることを専用の検査で保証する。一般的なLP残差上限1e-7は緩めていない。この数値精度はPHA質量目的の単位とは別であり、生物学的な死滅速度ではない。指定された非ゼロ維持費を勝手にゼロへ変更する処理でもない。

この変更は同一LPの解法変更とは異なるため、全比較を新しい同一ソースで再計算した。停止していた条件は最終修正版で1時間分の予備計算を通過した。

### ちょうどゼロになるC30と二次LPの偽の不成立

NS21単独・NS21+Pfの対照では、C30生成量と消費量が一致すると浮動小数点の丸めで微小負値が生じ、厳密な非負入力検査で停止した。−1e-12 mmol/L以上の負値だけを0へ補正し、ゴム分解のC5当量残差へ6倍の補正量を加える。酸素の探索試行ごとには累積せず、採用した内部ステップの補正量だけを物質台帳に残す。大きな負値を消す処理ではない。

さらにNS21単独の2条件では、一次目的の解が一般的な残差上限1e-7を満たしても、二次目的へ渡す目標を1e-9より大きく過大評価し、二次LPの全解法が不成立になる場合があった。二次LPが失敗した時だけ一次目的から高精度で再計算する。培地・時刻・元の制約・受理精度を変えないが、二次LPの数値的な保持目標は作り直すため、同一LPの再試行とは区別する。取り下げた要求は `superseded_uncertified_requests`、再計算履歴は `primary_recomputations` へ記録する。数値失敗を死滅速度や0生産へ置き換えない。

実行中のソースを固定するため、先に明示的な補正アダプターで失敗した対照だけを新しい出力先へ再実行した。元の成功軌道は全試行でC30非負・二次LP成功だったので、2つの追加条件分岐が発動しない。これは動態計算の限定的な同等性であり、ソースのハッシュが同じという意味ではない。失敗結果・再実行・採用元を保存し、最も大きなPHA量を選ぶことはしない。通常の `AuditedDFBASimulator` へ統合し、その時点の酸素予約方式で通常版と補正対照の12h全時系列の一致を検証した。これは次節の共有酸素方式への変更前の同等性検査である。方策契約にも修正リビジョンを含めた。

### 追加監査：未使用の酸素予約と定常DOの刻み依存

前段の23ケースは酸素収支を満たしたが、低kLaの3種の終点DOが0.025/0.0125/0.00625 hに対し0.02549/0.01467/0.007918 mmol/Lとなった。最大取り込み能へ比例配分すると、LPが使わなかった酸素も予約されたままとなり、定常DOに時間刻みが入り込む。総収支の閉鎖だけではこの不具合を検出できなかった。

独立したtoy GEMで、Aは酸素を消費し、Bは同じ取り込み上限を持つが消費経路が停止している状況を作った。菌量・培地を固定し、kLa=1 h⁻¹、飽和DO=0.25 mmol/L、Aの酸素上限=20D/(0.01+D)とすると、連続時間の平衡はD=0.000126517 mmol/Lである。旧比例配分は刻み0.1/0.025/0.00625 hで0.021723/0.006024/0.001548となり、新方式は全て解析値から1e-8 mmol/L以内になった。新方式ではBの未使用取り込み上限の有無でも平衡が変わらない。実菌の速度定数を同定した試験ではなく、数値配分の欠陥を切り分ける試験である。

この変更は動態を変えるため、前段の23ケースを `results/audited_symbiosis_20260908` に保管し、全23ケースを `results/audited_symbiosis_shared_oxygen_20260908` へ同じ新ソースで再計算した。旧結果の約3.8%という3種差を新方式の結論として流用しない。原因の記録は `oxygen_quota_followup/isolated_defect.json`、回帰試験は `tests/test_shared_oxygen_coupling.py` にある。

### LPの多重最適解と交換フラックスの選択

増殖/PHAの最適値だけでは、NH4や鉄などの交換が一意に定まらない場合がある。新参照の既定 `flux_selection='parsimonious_exchange'` は、一次目的値の劣化を絶対値1e-9以内に制限したうえで、物理的な交換フラックスの絶対値の和を最小化する。選択から除外する交換はH、水、細胞内PHA/PHV、ゴム境界であり、「全反応のフラックスを最小化する」処理とは異なる。`'primary_only'` も比較用に指定可能。

これは不要な交換を抑える**解選択の仮定**である。実測された代謝フラックス、独立した共生根拠、一意解の保証ではない。細胞内の循環や残る縮退はあり得る。`flux_selection` を変えた結果を同じ方策・教師の契約へ混ぜない。

### GEMを変更する場合の入力契約

新参照は作業用GEMをコピーし、初期化後の反応追加、化学量論、目的係数、GPR、分子式、電荷、区画、制約数などの構造変更を検出して、供給や培養状態を更新する前に拒否する。GEMを変更する場合は、対応するモデル契約を持つ新しい参照インスタンスを作る。

任意の追加LP制約を黙って落とすことも避け、未対応の追加制約は拒否する。**0を含まない必須フラックス境界は、内部反応・交換反応とも現参照では未対応**。`density_policy='none'` でもpH係数による全細胞フラックスの縮小が残るため、この拒否を解除しない。維持ATPの正の下限を使うには、制約を保つ別の実装と検証が必要であり、下限をゼロに戻すことを生物学的な修正とみなさない。

### 炭素監査の更新前状態の保存

予備計算で `src/audited_dfba.py` の `_prepare_oxygen` が、更新前の培地辞書を更新用状態と共有し、炭素収支の「更新前」を更新後の値で計算していた。独立した辞書のコピーへ修正した。これは**監査値の算出**に対する修正であり、この差をLP解・GEMの改善による増産として計上しない。ゴム/C30/ODTD部分の実際のC5当量保存と監査値の一致を回帰試験で確認した。分子式欠落を含むGEM全体の元素収支は別の検査である。

### 背景培地の炭素・窒素を数量化

初期培地の直接対応するGEM分子式から、NH4以外に既知窒素3.01 mmol-N/L、既知有機炭素8.89 mmol-C/Lを確認した。NH4は0.05 mmol-N/Lであり、既知全窒素3.06 mmol-N/Lの1.63%に過ぎない。背景窒素の内訳は核酸関連1.76、ビタミン・補因子1.12、アミノ酸0.08、有機鉄錯体0.05 mmol-N/L。直接対応する定義のない7成分は未確定とした。

基準の外部乳酸投入は12hで9 mmol-C/Lなので、背景有機炭素も無視できない量である。これらは含有量であり、利用可能性、同化量、PHAの起源を証明しない。NH4だけの値から全窒素欠乏を判断することはできない。根拠と成分別表は `results/cultivation_model_audit_20260908/medium_element_inventory.json` と `medium_element_inventory_JA.md` に保存した（B01・B07の量的補足）。

## 新参照の起動例と再利用条件

WSLのプロジェクトルートで `main.py train --help` を確認し、以下の引数が受理されることを確認した。下記は新しい構成での小規模な起動例であり、この文書のために学習を実行したものではない。64stepの指定は有効な制御方策の完成を意味しない。

```bash
.venv-cuopt-26.8/bin/python main.py train \
  --consortium-profile pf-helper3 \
  --dynamics audited \
  --solver-backend highs --fba-mode separate \
  --control-dt 1 --internal-dt 0.025 \
  --initial-rubber 10 --initial-nh4 0.05 --ph-target 7 \
  --observation-schema metabolic_v2 \
  --max-specific-feed-rate 0.1 \
  --max-steps 12 --n-envs 1 --device cpu \
  --total-timesteps 64 --n-steps 16 --batch-size 16 \
  --eval-episodes 1 \
  --output-dir outputs/audited_pf_example_new
```

このmain経路の既定接種量はOR16=0.5、NS21=0.1、Pf=0.1g/Lであり、共生比較のPf=0.03g/Lとは異なる。比較スクリプトの設定を上のCLI例で再現したと解釈しない。実際の菌量、指定培地とreset後培地、制御スキーマなどは `cultivation_configuration.json` へ保存する。実験設計が異なる場合は新しい出力先を選ぶ。

`audited` では `highs` / `separate` が必須。GPU surrogateやcooperative教師にこの新参照を接続済みとは説明しない。既存の収集経路はlegacy cooperativeを明示した契約を持ち、今回の新参照の教師ではない。

本作業では、旧教師と新参照の教師、異なるGEM・供給単位・解選択・パラメータのデータを、**同じ学習/選択/評価集合へ混在させない**。旧データに後から新しい由来を付けて整合したことにせず、必要な場合は新しいデータセットとして収集・検証する。既存の収集失敗や未完了シャードを、別seedへの差し替えや削除で隠さない。
