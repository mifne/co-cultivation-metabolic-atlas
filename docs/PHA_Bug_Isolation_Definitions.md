# 仮説と問題の切り分け定義書 (PHA蓄積不全のデバッグ)

## 現状の課題
`tests/test_degradation_potential.py` において、`Actinoplanes sp. OR16` によるゴム (rubber) の完全分解（100 g/L -> 0 g/L）が確認された。しかし、最終的なアサーションにおいて `Rhizobacter gummiphilus NS21` の PHA 蓄積量が `0.0000 mmol` となり、テストが失敗している。代謝のバケツリレー（ゴム -> ODTD -> PHA）の後半部分が機能していない。

## 仮説の設計

現状の事象を説明しうる仮説として、以下の4つを設計した。

1. **仮説1: OR16による中間代謝物の分泌不全**
   OR16がゴムを吸収したものの、`odtd_e` や `rubber_fragment_e` として環境中に分泌せず、すべてCO2やバイオマスとして消費（完全酸化）してしまっている可能性。
2. **仮説2: NS21による中間代謝物の取り込み不全**
   OR16から環境中に中間代謝物（ODTD等）が分泌されているにもかかわらず、NS21側の取り込み反応の境界条件（Bounds）が閉じているか、シミュレータの環境更新ロジックで種間の物質移動が正しく反映されていない可能性。
3. **仮説3: 窒素過剰によるPHA蓄積経路の非活性化（生物学的・熱力学的制約）**
   現在のテストコードでは、毎ステップ `nh4_e = 1000.0` と無尽蔵に窒素を補充している。生物学的に、PHAは炭素源が豊富かつ「窒素等の栄養塩が枯渇（Limitation）」しているストレス条件下で蓄積される。窒素が豊富すぎるため、炭素がすべてバイオマス合成（増殖）に回っており、PHA蓄積フラックスが最適解として選ばれていない可能性。
4. **仮説4: シミュレータ側でのPHA記録ロジックの不具合**
   FBAのフラックス上はPHAが生成されているにもかかわらず、`dfba_simulator.py` 側で `ns21_state.pha_accumulated` 変数へ値を加算・記録する処理に欠陥があるか、ターゲットとする反応名（例: `EX_pha_c` 等）がモデルとシミュレータ間で不一致を起こしている可能性。

## 問題を切り分けるためのテストコード実装方針

上記の仮説を検証・除外するため、どのようなテストコードの修正・拡張を行えばよいかを以下に定義する。

1. **OR16の分泌フラックスのアサーション追加 (仮説1の検証)**
   テストループ内で、OR16の `metabolite_secretion` を監視する。`odtd_e` または `rubber_fragment_e` の分泌量が `> 0` になっているかをプリントし、アサートする。ここで分泌が確認できなければ、OR16の代謝モデルに問題がある。
2. **NS21の取り込みフラックスと環境中濃度の監視 (仮説2の検証)**
   シミュレータの環境変数 `state.metabolites['odtd_e']` の濃度が時間とともに上昇または変動しているかを確認する。同時に、NS21の `metabolite_uptake.get('odtd_e', 0.0)` 等が `> 0` になっているかをプリント出力して確認する。
3. **窒素枯渇条件（Nitrogen Limitation）の導入 (仮説3の検証)**
   テスト環境での `nh4_e = 1000.0` の毎ステップ補充ロジックから `nh4_e` を除外する。あるいは初期濃度のみを与え、途中から窒素枯渇状態を作り出す。バイオマス増殖が停止した後に、PHA蓄積にフラックスが切り替わるかを検証する。
4. **手動OptimizeによるPHAフラックスの直接確認 (仮説4の検証)**
   テストループ内で、OR16だけでなくNS21に対しても手動で `.optimize()` を実行し、得られた解（`sol.fluxes`）の中にPHA生成関連のフラックスが存在しているかを直接プリント出力する。フラックスが出ているのに最終的な `final_pha` 変数がゼロのままであれば、シミュレータの実装バグ（仮説4）と断定できる。

## サブエージェントへの実行指示
この定義書を受け取るエージェントは、以下の手順で作業を進めること：
1. 本ドキュメントの「問題を切り分けるためのテストコード実装方針」に基づいて、既存の `tests/test_degradation_potential.py` にデバッグ用のプリント文や、窒素枯渇条件の変更、アサーションを追加するプランを立てる。
2. プランを実行し、テストを走らせることで、どの仮説が真の原因であるかを特定する。
3. 原因が特定できたら、それに応じてテストスクリプト、モデル改修スクリプト（`scripts/modify_*.py`）、またはシミュレータ（`src/dfba_simulator.py`）を適切に修正する。
4. 最終的に、テストにおいて「ゴムの減少」と「NS21によるPHA蓄積（> 0.0）」の両方がPASSする状態（バケツリレーの完全動作）を実現すること。
