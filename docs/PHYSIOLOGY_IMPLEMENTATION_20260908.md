## 窒素判定の意味

NS21について、実際の最大増殖速度を μ、窒素取込だけを緩めた仮想条件の速度を μN とし、配分係数を `min(1, μ/μN)` とする。μN が1e-9 h⁻¹以下なら係数を0とする。PHA最大化LPへ指定する増殖下限は、この係数 × μ。これは生理学的に校正された法則ではなく、明示的な解選択規則である。

仮想条件で緩めるのは、同定済みのアンモニウム取込だけ。アミノ酸などの取込を増やすと炭素供給まで増えるため、それらは緩めない。硝酸等の電子受容体も追加しない。仮想条件にも元の最大取り込み上限を残すので、完全な窒素無制限を証明する計算ではない。実際の全窒素源の利用は通常のGEM制約で扱う。仮想解の供給・消費は培地へ積分しない。

初回の6ケースでは分子式からNのみの成分を自動選択したが、GEMのTNTがNO2と記載されるなど、炭素の欠落した有機化合物が混ざる問題が見つかった。初回は `initial_probe/` にソースとともに保存し、最終方式へ混ぜない。アンモニウムだけの緩和へ修正し、トルエン・ベンゼン名なのに炭素を持たない分子式も既知元素集計から外して未分類へ記録した。これは全分子式の正しさを保証する辞書ではない。

旧NH4式は比較用の明示設定 `nitrogen_policy="nh4_legacy"` として残した。新経路の既定は `capacity_ratio`。

## 維持代謝と死滅の数値契約

指定された反応が ATP + H2O → ADP + Pi + H の単位反応であり、元素・電荷が釣り合うことを確認する。任意のATP消費反応やキナーゼを維持反応として受け付けない。対象モデルではOR16/NS21の `ATPM`、Pfの `rxn00062_c0` が該当する。

各酸素試行で、維持ATP生成・消費の実行可能量を先に求め、後段の増殖/PHA計算でその量を保つ。密度・pH倍率を s とすると、LPでの要求は要求実速度/s。実現可能量の保持精度は1e-9。酸素の試行解は物質台帳や死滅へ累積せず、採用された内部ステップだけを積分する。

要求を満たせないときは、数値失敗を死滅へ置き換えるのではなく、認証された実行可能解から不足率 `max(0, 1−実現ATP/要求ATP)` を計算する。死滅率は `基礎死滅率 + 最大飢餓死滅率 × 不足率`。菌体増加を計算した後に `exp(−死滅率×Δt)` を掛け、失われた分を死菌区画へ保存する。一般の増殖と死滅の連成には有限刻み誤差が残る。

死菌区画は代謝も溶菌も行わない。死菌中のPHAはlive PHA報酬へ加えず、診断出力に別記する。培養液全体からの抽出可能量と同義ではない。採液は死菌の物質量を記録し、代表採液では残る濃度を変えない。

`maintenance` と死滅率を省略した場合、測定値を捏造せず0相当となる。以下の例は非ゼロ仮定を与える動作例であり、推奨培養パラメータではない。

## B12注釈で実際に変更したこと

NS21のMETSは元の `A4W93_27845 or A4W93_24875` から `A4W93_24875` へ変更する。ローカルFASTAの前者に `[pseudo=true]` が明記されているため。元GEMは保存し、作業コピーへ適用する。注釈修正したSBMLも結果ディレクトリへ保存する。反応の化学量論やフラックス境界は変えない。

残るA4W93_24875の注釈は 5-methyltetrahydropteroyltriglutamate--homocysteine methyltransferase。注釈名だけで完全長酵素の機能、B12非依存性、発現を確定しない。OR16のMETSにはACTI_38740（metH注釈）とACTI_79740（cobalamin-binding protein注釈）が含まれ、後者を完全な代替酵素とみなせるかは未確定のため自動削除しない。

METSの正味反応式に触媒補因子B12がないことだけでは、生物学的な非依存性も依存性も判断できない。B12関連遺伝子の一部が見つかったことも、合成・輸送経路が機能する証明ではない。注釈・元規則・変更内容・FASTA SHA256は `b12_evidence.json` に保存した。

## 実行と再利用

WSLのプロジェクトルートから次の設定で新経路を選択する。JSONは実GEM検証が出力する例で、各菌の維持ATPを0.1 mmol/g/h、基礎死滅率0.01 h⁻¹、最大飢餓死滅率0.1 h⁻¹としている。値は全て未校正。

```bash
.venv-cuopt-26.8/bin/python main.py train \
  --dynamics physiology --consortium-profile pf-helper3 \
  --physiology-config results/physiology_implementation_20260908/example_uncalibrated_physiology.json \
  --solver-backend highs --fba-mode separate \
  --control-dt 1 --internal-dt 0.025 \
  --initial-rubber 10 --initial-nh4 0.05 --ph-target 7 \
  --observation-schema metabolic_v2 \
  --max-steps 12 --n-envs 1 --device cpu \
  --total-timesteps 64 --n-steps 16 --batch-size 16 --eval-episodes 1 \
  --output-dir outputs/physiology_example_new
```

これはCLI起動例であり、本作業でRL学習を完了した意味ではない。CLIの既定接種量と、確認スクリプトの接種量は異なる。新しい条件を指定したインスタンスを作り、構築後の生理設定変更は拒否する。方策契約にも同じ設定を保存する。
