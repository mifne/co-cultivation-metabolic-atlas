# GPU多段LP実装の検証（2026-09-04）

## 結論と対象

OR16・修正済みNS21（PHB/PHV）・P. freudenreichii の同じdFBAを比較した。
旧来の逐次CPUに対する限定的な高速化は確認済みだが、今回追加した
**4並列CPUに対して安定して高速な実装は未達成**。完全GPU常駐の環境でもない。
失敗した計算の所要時間は高速化率に含めていない。

「1ステップ」は培養時間0.2 h分の状態更新であり、PPOの10万ステップ学習全体ではない。
8環境×各1ステップは計8回、16環境×各1ステップは計16回の状態更新を指す。

## 実測（すべて秒、初回準備を除く反復）

|比較条件|CPU|GPU|CPU時間 / GPU時間|結果|
|---|---:|---:|---:|---|
|2環境×1ステップ、逐次CPU、既報の1反復|2.415|0.947|2.550|精度合格。ただし並列CPUとの比較ではない|
|8環境×1ステップ、4並列CPU、GPU一律64反復枠|3.478 / 3.382|4.575 / 4.516|0.760 / 0.749|全環境合格、GPUは遅い|
|8環境×1ステップ、4並列CPU、多段修正|3.505 / 3.514|3.828 / 3.915|0.916 / 0.898|全環境合格、GPUは遅い|
|16環境×1ステップ、4並列CPU、多段＋有効部分の行列演算|6.773|7.552|0.897|全環境合格、GPUは遅い|

反復数が少なく、信頼区間や有意差は主張しない。上記は同一条件の反復であり、
独立した多数条件への汎化を示すものでもない。初回GPU時間は上表より長い。
16環境の初回はCPU 6.945 s、GPU 8.479 sだった。

## 公平性・精度

- CPUは従来の3段LP目的関数を維持。HiGHS dual simplex、LPごとにthreads=1、
  parallel=False。4ワーカーにLP配列だけを渡し、COBRAオブジェクトはスレッド共有しない。
- GPUは同じ3段LPと、既存の最適解選択用4段目を使用。CPUの目的関数は変更していない。
- LP組立、転送、ホスト側振り分け、GPU修正、状態更新をオンライン時間に含める。
  辞書構築・読み込み、環境複製は別枠。初回オンラインのグラフ構築は時間に含む。
- GPU区間ではCPU最適化呼び出しを禁止し、CPU LP呼び出し0を確認した。
- 元LPの主残差≤1e-5、双対残差≤1e-7、相対数値KKT gap≤1e-7。
  PHA相対誤差≤1%、菌体量絶対誤差≤0.01 g/L、PHV比率絶対誤差≤0.01。
  菌体量とPHV比率の基準を「相対1%」とは呼ばない。
- 16環境の1ステップでは、PHA相対誤差最大3.85e-13、菌体量最大1.36e-13 g/L、
  PHV比率最大6.74e-13。これはCPU数値解との一致であり、実験精度の保証ではない。

## 実装変更

1. 独立環境を次のLP呼び出しまで進め、同じ段のLPをGPUにまとめて投入。
2. 基底辞書で認証→小さなGPU修正→不合格行だけ大きなGPU修正。
3. 4段目はまず反復なしで元LPの証明条件を検査し、必要時だけ追加反復。
4. CUDAグラフのキャッシュ不足を修正し、繰り返し再構築を削減。
5. GPU上のカウンターで有効な基底更新数を追跡し、未使用の厳密な単位行列部分を
   消去計算から除外。近似・桁落とし・許容誤差緩和ではない。
6. 2段目が辞書から修正できないとき、直前の1段目の実行可能な基底から再最適化。

## 残るボトルネック

8環境×2ステップでは、1ステップ目は全件完了するが、2ステップ目の2段LPで
6環境が最適性基準に達しない。1段目基底からの再最適化によって主残差は
約1e-12に改善したが、64反復後も双対残差とgapが大きく、不合格として停止した。
これを2ステップ完了や高速化とは報告しない。

高速化試験用の基底バンクは元々各段4基底であり、過去の32,768件のsurrogate辞書とは
別のもの。追加の独立訓練seed 20286501–20286504で2段LP基底を構築し、網羅性を改善する。
検証seed 20286411以降のLPを追加学習に流用しない。構築費用と出典ハッシュを記録し、
数値基準を変えずに2ステップ以上の比較を再実行する。

### 辞書拡張後の確認結果

独立訓練4 seed×2ステップで8個の追加基底を作成し、2段目を4→12基底に拡張した。
費用はCPU LP 24回、準備・訓練18.63 s、因数分解52.15 s、計70.78 s。
これは事前計算であり、オンラインCPUフォールバックではない。

`pf_gpu_microbatch8_cpu4_extended_step2_20260904.json` では、2ステップ目の2段LPは
直接辞書認証3件、GPU修正を含めると6/8件が合格し、不合格が6→2件へ減った。
残り2件は最適性に達せず、全環境を1ステップ完了時点で停止している。
「6環境が2ステップ完了」とは解釈しない。CPU 7.290 sは全2ステップ分、GPU 8.779 sは
失敗までの時間なので、両者から高速化率を算出しない。

辞書を増やすだけでも効果はあるが、全基底を毎回調べるコストも増える。
次は訓練分布の追加と基底選択の高速化をセットで行い、残る2件の非収束を調査する。
現時点では学習用の既定バックエンドへ切り替えない。今回の全計算は終了済み。
