# 低次元GPU LP実装と速度検証（2026-09-04）

## 実装した構成

1. 既存の低次元パラメトリック辞書で候補解を計算し、元のLP全体で検証する。
2. 不合格環境だけ、K本の非基底方向を選び、基底変数を消去した M×K の表でGPU最適化する。今回の継続型実験では K=64。Kは実験設定値であり、普遍的に十分と保証した次元数ではない。
3. 元のLPの制約・双対・ギャップを再評価し、不足する方向を選び直す。直前の基底を引き継ぐため、各回を初期解から解き直さない。表の幅Kと、引き継ぐ基底差分のランクは別の量である。
4. なお不合格の場合だけ、既存の全変数GPU補正へ進む。オンラインCPU LPへのフォールバックは禁止した比較を行う。

主なコード: `src/gpu_restricted_basis.py`、`src/gpu_batched_compiled_backend.py`。近似PCAで反応を削除する方法ではない。GEMの反応、培地、目的関数および合格基準は変更していない。

## 精度と比較条件

- 元のLP: primal ≤ 1e-5、dual ≤ 1e-7、relative KKT gap ≤ 1e-7。
- 軌道終点: PHA相対誤差 ≤ 1%、菌体濃度最大絶対誤差 ≤ 0.01 g/L、PHV割合絶対誤差 ≤ 0.01。
- CPU: 元の3段階HiGHS、4並列ワーカー、各LP 1スレッド。
- GPU: RTX 4060 Laptop、同じ初期状態・操作列・3段階目的関数。
- 2ステップは各環境0.4時間分の培養状態更新（dt=0.2 h）。120ステップや強化学習全体の計測ではない。
- 総時間にはホストの状態更新・LP組立、転送、失敗候補、全補正、実行中の初回グラフ生成を含む。静的な辞書読込、事前演算子構築、環境オブジェクト作成は別計上。
- 以下は独立学習データとは重複しないが、繰り返し調査した開発用seedである。未観測条件での一般的な高速化・長期精度を示すものではない。

## 確認した律速と残る課題

低次元内では最適でも、未選択の方向に改善余地が残るため、複数回の列生成が必要になる。64方向の計算自体だけでなく、方向選定・元LP検証・基底の復元・グラフ作成と小さい環境群のホスト制御が積み重なる。

また、終了済みグラフの出力配列が残ると、その専用メモリプールの空き一時領域も保持され得た。グラフ終了時に不要な領域だけを解放する修正を行い、外部に渡した結果が引き続き有効であることをテストした。単一の保存済みLP・12回列生成の診断では、終了時デバイス使用量が2.699 GBから1.719 GBに減った。これは全dFBAのピーク使用量ではない。

次の検証では、増殖段階の基底の再利用と、より大きい環境群での並列効率を測定する。合格した短軌道の総時間がCPUより短くなってから、新しいseed・長い軌道・120ステップに進む。ホスト側dFBA状態更新は残っており、完全GPU内完結とは呼ばない。

追記: 増殖段階の早期再利用は上表のとおり遅くなり、不採用。64環境・補正8並列は最終段階で約7900 MiBのVRAM使用と停滞を再現し中止した。CPUは55.849秒だったが、GPUの完走時間・最終精度・速度比は存在しない。中止した試行も `results/pf_restricted_poolfix_64x2_20260904.json` とログに残している。

グラフ再利用は、基底差分領域を段階的な容量に揃える方式で実装した。未使用部分は厳密にゼロであり、代謝方向を打ち切るための閾値ではない。同一LPであることを確認した直前の状態を再利用し、不要な実行準備と重複した再計算を減らした。元データは `results/pf_restricted_bucket_8x2_20260904.json`。

既存の大きい辞書（maxmin/aggregate/exchange = 44/52/44基底）を組み合わせた16環境×2ステップも完走し、両反復で精度基準を通過した。ただしCPU 14.672 / 15.129秒に対してGPU 55.742 / 41.770秒で、CPU超えではなかった。元データは `results/pf_restricted_bucket_fullbank_16x2_20260904.json`。辞書サイズの拡大だけを改善策として採用しない。すべての計測は終了しており、バックグラウンドのベンチマークは残っていない。

本実装で引き継いでいる低次元補正の基底は、主に同じLPの列生成ラウンド間のものであり、培養時間ステップ間の再利用とは区別する。時間ステップでは菌体量と培地状態を更新し、その結果が次のLPの入力になるため、同一環境の時間方向は独立ではない。独立に並列実行できるのは別環境や、入力状態がすでに与えられた事前計算用LPである。
