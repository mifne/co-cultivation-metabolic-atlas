## 優先案：予測を答えにせず、検証付きの開始点にする

1. 現行GEM・同一3段階目的で得た基底と非基底の上下限状態を保存する。
   モデルハッシュ、反応ID、段階、前処理対応を含める。
2. GPUで候補基底を選び、基底方程式をバッチで解く。
   原問題の可行性だけでなく、被約費用の符号条件と目的値も確認する。
3. 元のLPに対する数値的な最適性判定を満たす候補のみ採用する。
   予測されたフラックスへの近さや辞書距離だけでは採用しない。
4. 候補が不適合なら、同じLPを解くGPU補正経路へ送る。
   数値計算の失敗を培養の死滅・負報酬に変換しない。

従来の「予測フラックスへ近づけるQP」と違い、予測が最終的な目的関数を置き換えない。
近似モデルは速度を助けるが、最終出力の受理条件は機構的LP側で決める。

### 第1段階に限った上限制約による証明（未実装）

開発用完走ログでは、120回中109回の第1段階が共通増殖の上限0.005 h⁻¹へ
1e-8以内で到達していた。第1段階はμを最大化し、μ≤0.005という既知の制約がある。
その時刻の全制約を満たし、μがこの上限に達する候補を検証できれば、
上限以上には改善できないので、その第1段階の目的値を確定できる。

これは最適性の上界を使う特例であり、単なる近似値の採用ではない。
候補の全GEM収支・上下限・共有培地制約を現在の状態で再検査し、不適合なら
従来のGPU LPを解く。候補作成が成功する割合は未測定であり、109/120を
そのままLP省略率・高速化率には換算しない。
第2・3段階にはこの上限証明をそのまま適用できないため、省略しない。
採用する場合は「GPU証明による解決」と「GPU反復LP求解」を別カウンターで記録する。

## バッチ化に向けた行列の整理（現行コードからの導出）

種iのフラックスをv_i、菌体量をX_iとする。
現行コードと同じ B_i = max(1e-12, X_i) を使い、z_i = B_i v_i と置く案を考える。
これは以下の線形問題での変数変換であり、代謝・培地条件の変更ではない。

|制約・目的|変換後|環境間での共有性|
|---|---|---|
|細胞内収支 S_i v_i = 0|S_i z_i = 0|S_iは固定|
|共有培地の交換量|交換の化学量論係数とz_iの積|主な交換行列が固定|
|反応上下限|B_i l_i ≤ z_i ≤ B_i u_i|上下限ベクトルが変化|
|共通増殖の下限 g_i v_i ≥ μ|g_i z_i ≥ B_i μ|μ列の菌体量係数が変化|
|ライブ目的 c_iᵀv_i| (c_i/B_i)ᵀz_i|目的係数が変化|
|交換絶対値の節約|補助変数 ≥ ±交換係数×z_i|主な制約係数が固定|

共通増殖列と第2目的保持行などは依然として環境依存である。
「完全に同じAをそのまま全環境で共有できる」とは扱わず、固定行列演算と
少数の可変項を別カーネルに分ける設計が必要。
極小菌体量では c_i/B_i が大きくなり、悪条件化する可能性もあるため、
元の変数へ戻した残差を必ず検査する。変換を導入するなら等価性テストを先に行う。

## 評価順序

1. 交換フラックスの解選択を解決し、回帰試験の後に新しい独立5条件の総合精度を確認する。
2. 可行性・被約費用を検査する基底候補選択を、同一状態のLPで比較する。
3. 基底キャッシュ、CUDA Graph、バッチ化を1つずつ追加し、変更ごとに精度回帰を確認する。
4. 環境数1/8/32/128などを実機メモリに収まる範囲で比較する。
   指標は環境ステップ毎秒、全環境の完走時間、修復率、最大誤差、メモリピーク。
5. CPU側も同じ問題・同じ精度で、逐次版だけでなく並列・基底再利用版を比較対象にする。
   遅いCPU実装だけを相手にGPU倍率を計算しない。
6. 最終評価に使った5条件は以後回帰試験とし、改善版には別の未使用条件を用意する。

GPU利用率100%やVRAM占有率だけを達成目標にしない。
精度・成功率・所要時間が改善して初めて、計算資源の有効利用が改善したと判断する。
