# RL効果確認後の次期実施計画

## 1. 現在地

現行の三種GEM–dFBA–PPO系は、24 h、5つの初期条件摂動、厳密HiGHS再計算において、
Fixed-25に対する事前定義効果判定を通過した。これは計算上のStage 2達成であり、三種共存、
ゴム分解、PHA生産および実機制御が実証されたことを意味しない。

次の目的は、学習step数を増やすことではなく、現在の制御則が依存している未校正仮定を減らし、
1 Lジャーファーメンターで検証可能な問題へ変換することである。

## 2. 現時点で不足しているもの

### 科学データ

- OR16、NS21、WCFS1の単独・二種・三種培養における菌種別増殖速度
- Glu、Ile、B6 vitamer、NH4、有機酸の取り込み・分泌時系列
- ゴム切断速度、酸素依存性、ODTD/オリゴマー生成、分子量低下
- PHA g/L、PHA %DCW、モノマー組成とモデル内PHAフラックスの換算
- 維持ATP、死亡・失活、競争係数、酸素移動、pH阻害の校正値
- 各交換反応の境界値について、文献、実測、仮定を区別したprovenance表

### 実機仕様

- 1 Lが最大容量かworking volumeか、初期液量と許容総添加量
- 4本の栄養ポンプの最小/最大流量、分解能、遅れ、脈動、実重量誤差
- 酸・塩基ポンプの濃度、流量、PIDログ、塩・液量の蓄積
- airflow、RPM、DO範囲と、ゴム添加時の `kLa=f(RPM, airflow, volume, rubber load)`
- 手動採取時刻、採取体積、補液の有無
- 実時間で利用できる観測と、オフライン分析でしか得られない観測の区別

### プログラム

- stock流量、希釈、液量増加、sampling減少を扱う `one_l_jar` profile
- 酸・塩基添加による液量、Na/Cl蓄積を含むpH-stat物質収支
- RPM/airflow/DO cascadeからkLaを計算する校正インターフェース
- ポンプ上限、変化速度、最小保持時間、センサー欠測を扱う安全層
- 実時間観測だけをPPO/SACへ渡す部分観測環境
- 多段誤差を評価するstate-transition surrogateと厳密解補正

## 3. 実施順序

### Phase A — 現行計算基準の凍結

1. 最終モデル、VecNormalize、SBML、設定、seed、コード、結果のSHA-256 manifestを作る。
2. 4,096-step結果を「pre-calibration baseline」と明記する。
3. GPU近似だけで得た軌跡を科学的endpointへ使用しない規則を固定する。
4. 共通培地0.25 safety capがモデルzipではなく環境wrapperに依存することを実行手順へ明記する。
5. 旧iNF517表記をWCFS1 2022へ統一し、Defined-10、Glu+Ile+pyridoxamine、
   succinate/MSG/mannitol/yeast extractの候補を「計算用」「小容量検証用」「実機候補」に整理する。
6. 現行24 h評価と、旧48 h/168 h実機案の目的を分け、次に採用する培養時間を固定する。

完了条件：新しい環境で同じ25評価軌跡と効果判定を再生成できること。

### Phase B — 1 L実機profileの実装

1. 状態にworking volumeを追加し、各ポンプをstock濃度とmL/hで表現する。
2. 流加希釈、蒸発、手動sampling、酸・塩基添加を物質収支へ含める。
3. pHは装置PIDの内側ループ、RLは栄養4本とDO/RPM setpointの外側ループとする。
4. 温度は最初は30°C固定とし、RL actionへ追加しない。
5. actionの上限、rate limit、dead time、ポンプ故障時のsafe actionをテストする。

完了条件：炭素・窒素・液量収支誤差が各0.1%以下で、実機に存在しない観測を方策が利用しないこと。

### Phase C — モデル科学監査と感度解析

1. 全exchange boundを「実測」「文献」「モデル既定」「仮定」に分類する。
2. Lcp/Roxゴム切断層について、元素収支、生成物、遺伝子根拠、速度式、酸素量論を再監査する。
3. NS21のPHA目的切替が実験的調節ではなくモデル仮定であることを分離し、連続的な蓄積式を検討する。
4. 未校正パラメータを同時に変動させ、PPO優越が消える領域を特定する。
5. 追加実験の情報価値を順位付けする。

完了条件：主要結論を反転させる上位パラメータと、その測定方法が一覧化されること。

### Phase D — 仮想パラメータによる計算受入試験

1. **完了:** 17実行（独立16条件＋決定論的再実行1回）の6時間smoke testで、液量、
   ポンプ、sampling、pH-stat、酸素移動、3種FBAの動作を確認した。詳細は
   `docs/ONE_L_JAR_SMOKE_REPORT.md` を参照する。系全体の炭素・窒素元素収支は、
   交換代謝物の化学式とポリマー擬似反応を監査した後の未完了項目とする。
2. 初期菌比、初期栄養、ゴム量、pump誤差、kLa、Lcp/Rox速度、PHA速度、維持ATP、
   死亡率を仮想範囲として定義する。各値には「文献範囲」「モデル由来」「仮定」のタグを付ける。
3. Latin hypercube等でまず128条件を厳密FBA並列計算し、共存、ゴム分解、PHA、液量、
   pH/DO、安全制約の成立率を求める。
4. 失敗境界と高感度パラメータへ追加256条件を配置し、単なる平均性能ではなく、
   実行不能率、最悪値、制約違反、policy regretを集計する。
5. 固定制御、機構ベースrule、現行PPOを同じ仮想条件で比較する。GPU近似値は探索に使っても、
   可否判定と図表は厳密FBAで再計算する。
6. 感度とvalue of informationから、wet-labで最初に測る項目と条件を順位付けする。

完了条件：少なくとも一つの実機実行可能な操作領域が仮想不確実性下で成立し、主要失敗原因と、
それを判別する最小実験セットが得られること。広い仮想範囲で三種共存が成立しない場合は、
実験へ進まず、菌種構成、流加液または反応モデルへ戻る。

### Phase E — 小容量wet-lab校正

1. 単独、主要二種組合せ、三種を比較し、各条件を最低3生物学的反復で実施する。
2. 基礎培地、選定3成分0.5×/1×/2×、主要欠損、Defined-10を優先する。
3. 0、4、8、12、24 hで菌種特異的qPCR/ddPCR、培地成分、NH4、有機酸を測る。
4. ゴム乾燥重量だけでなくFTIR、SEC/GPC、ODTD/オリゴマーを測る。
5. PHAはg/Lと%DCWをGC-FID/GC-MS等で独立測定する。

完了条件：全三種の維持と、少なくともゴム切断またはPHA蓄積の正の実測が再現し、校正用時系列が得られること。成立しない場合はRLを進めず、菌種構成または培地設計へ戻る。

### Phase F — パラメータ推定と外部検証

1. 培養データを校正用とholdout培養日に分ける。
2. 増殖、取り込み、ゴム切断、PHA蓄積、酸素移動、pH阻害を同時校正する。
3. endpointだけでなく時系列誤差、菌種別誤差、物質収支を適合指標にする。
4. holdout培養を使い、校正後モデルの予測区間被覆率を評価する。

完了条件：未使用培養日の三種菌体、ゴム、PHA、主要栄養の時系列が事前許容範囲へ入ること。

### Phase G — ロバストRLの再学習

1. 校正後のパラメータ不確実性をdomain randomizationへ入れる。
2. 報酬と制約判定を分離し、培地予算、共存、pH、solver、安全上限はhard constraintとして扱う。
3. PPO、SAC、機構ベースrule、固定制御を同じ計算予算で比較する。
4. 独立20 seed以上を目安に厳密FBA評価し、平均だけでなく最悪値、違反率、95% CIを報告する。
5. センサー欠測、ポンプ±10%、初期菌比、kLa誤差、sampling遅延をstress testする。

完了条件：強いrule-based対照に対しても効果または明確な資源削減があり、全seedで安全制約違反がないこと。

### Phase H — GPU architectureと購入判断

1. 既存のflux辞書検索ではなく、environment stateを一括更新するdevice-resident batchを作る。
2. GPUごとに辞書/モデルを1コピーだけ持つowner processとし、環境要求をmicro-batchする。
3. exact correctionを使うactive learningで、PHA・ゴム・菌体の24 h誤差を直接最小化する。
4. RTX 4060 Laptopで環境数1、4、16、64、256を測り、throughput、GPU使用率、VRAM、CPU時間を記録する。
5. 厳密FBAに対し24 h endpoint誤差1%以下、solver/物理違反0、end-to-end 3倍以上を受入条件とする。
6. 3 GPU予測は、単GPUでbatch scalingが成立してからseed/agent/environment shardとして算出する。

購入判断：上記精度条件を保ったままGPU使用率60%以上と環境数に対する明確なthroughput scalingが得られた場合に、RTX PRO 4000複数枚の根拠とする。現行の6対5 steps/sだけでは3 GPU購入根拠にしない。

### Phase I — 遺伝子ノックアウト探索

1. ノックアウトは毎時の制御actionではなく、培養前に固定するstrain-design変数として扱う。
2. essentiality、FVA、single/double knockoutで候補を絞り、実行不能株を除く。
3. 候補株ごとに流加policyを最適化する二階層設計とする。
4. 遺伝子ID registry、GPR、実験可能性、成長低下、PHA増加、三種維持を同時評価する。

開始条件：野生型三種系の小容量共存と校正後モデルが成立していること。

## 4. 最優先の次作業

最初に実施するのはPhase B–Dである。`one_l_jar` profileの仕様書を固定し、交換境界・ゴム切断・
PHA蓄積のprovenance表を作った後、仮想値による受入試験と感度解析を行う。この結果から、
成功確率と情報価値の高いwet-lab条件だけをPhase Eへ送る。10万step学習、SAC比較、
ノックアウト探索またはGPU辞書拡大は、仮想受入試験の後に判断する。

## 5. 実施前に確定が必要な入力

- ジャーファーメンターのメーカー・型番、working volume、airflow/RPM/DO仕様
- 4栄養ポンプと酸・塩基ポンプの流量範囲、stock容器容量、制御API/ログ形式
- 使用予定のゴム形態、粒径、初期量、前処理
- 利用可能なqPCR/ddPCR、HPLC/LC-MS、GC、FTIR、SEC/GPC設備
- 1 run当たりの採取体積と許容run数
- 実際に入手済みの3菌株と培養・安全SOP
